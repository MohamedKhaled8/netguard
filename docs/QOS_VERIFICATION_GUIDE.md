# NetGuard AI: Meeting Mode QoS & Verification Guide

This guide establishes the empirical verification protocol for NetGuard AI's Windows QoS and Meeting Mode priority engine. It specifies the technical citations, precedence proofs, PowerShell verification lifecycle, Wireshark packet capture procedures, and an A/B manual test matrix across all supported meeting platforms.

## 2. Policy Persistence in ActiveStore & Lifecycle Architecture

### Real Windows ActiveStore Behavior
A common misconception is that policies created with `-PolicyStore ActiveStore` disappear when the application that created them terminates. **They do not.**

1. **Survival across Process Termination:** Policies created in `ActiveStore` live in the Windows kernel Network Packet Scheduler (`pacer.sys`). If NetGuard crashes, is killed via Task Manager, or exits without running cleanup, the policies **remain active and enforced** in the OS.
2. **Reboot Scope:** `ActiveStore` policies are cleared **only by a system reboot** or an explicit call to `Remove-NetQosPolicy`.
3. **Mandatory Architectural Safeguards:**
   - **Startup Sweep:** On launch, NetGuard immediately enumerates and removes any stale `NetGuard_*` rules from `ActiveStore` and persistent stores.
   - **Process Termination Watchdog:** NetGuard registers `closeEvent` cleanup and an instant kill switch to wipe all rules.
   - **Reconciliation Engine:** A background watchdog reconciles active rules against confirmed active sessions every 30 seconds.

## 3. Strict Precedence Hierarchy & Demotion Protection

Windows evaluates QoS policies by their `-Precedence` integer (higher integer wins). NetGuard assigns explicit precedence values to guarantee that the background catch-all policy (`-Default -DSCPAction 8`) cannot demote DNS, meeting signaling, or monitoring probes:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ Precedence 200: Meeting UDP Media (DSCP 34 / 46)                            │
│                 NetGuard_Zoom_Media_*, NetGuard_Teams_*, NetGuard_Meet_*,   │
│                 NetGuard_Zoom_ScreenShare_cpthost_*, NetGuard_*_Fallback_UDP│
├─────────────────────────────────────────────────────────────────────────────┤
│ Precedence 170: NetGuard Monitoring Probes & Self-Exemption (DSCP 0)        │
│                 NetGuard_Exempt_App (netguard.exe), NetGuard_Exempt_Python  │
├─────────────────────────────────────────────────────────────────────────────┤
│ Precedence 160: DNS Queries Exemption (DSCP 0 - Best Effort)                │
│                 NetGuard_Exempt_DNS_UDP (Port 53), NetGuard_Exempt_DNS_TCP  │
├─────────────────────────────────────────────────────────────────────────────┤
│ Precedence 150: Meeting TCP 443 Signaling & Fallback Exemption (DSCP 0)     │
│                 NetGuard_Exempt_zoom_TCP443, NetGuard_Exempt_teams_TCP443   │
├─────────────────────────────────────────────────────────────────────────────┤
│ Precedence 100: Bulk Application Outbound Throttling (DSCP 8 + ThrottleRate)│
│                 NetGuard_Throttle_onedrive.exe, NetGuard_Throttle_dropbox   │
│                 (No -IPProtocolMatchCondition -> throttles TCP sync!)       │
├─────────────────────────────────────────────────────────────────────────────┤
│ Precedence 50:  Default Catch-all Background Demotion (DSCP 8 -> AC_BK)     │
│                 NetGuard_Default_CS1 (-Default -DSCPAction 8)               │
└─────────────────────────────────────────────────────────────────────────────┘
```

### Wireshark Filter Verification Protocol

Capture on the active physical network adapter while running traffic:

| Target Traffic | Wireshark Display Filter | Expected DSCP in IP Header | Precedence Winning Reason |
| :--- | :--- | :--- | :--- |
| **DNS Queries** | `udp.port == 53 \|\| tcp.port == 53` | `0x00 (DSCP CS0)` | Precedence 160 wins over Precedence 50 (-Default). DNS is never demoted to AC_BK. |
| **Meeting Signaling** | `tcp.port == 443 && (ip.dst in <Vendor_IPs>)` | `0x00 (DSCP CS0)` | Precedence 150 wins over Precedence 50. Signaling and control channels stay CS0. |
| **Meeting UDP Media** | `ip.dst == <Vendor_IP> && (udp.port in {8801..8810, 50000..50059, 19302..19309})` | `0x88 (DSCP AF41 / 34)` | Precedence 200 marks outbound media into AC_VI. |

| **Bulk Cloud Sync** | `(ip.src == <Host_IP>) && (!udp.port == 53) && (!tcp.port == 443)` | `0x20 (DSCP CS1 / 8)` | Precedence 100 applies CS1 demotion and rate cap; unclassified falls to Precedence 50. |

## 4. Manual Verification Test Matrix

Apply this identical 6-step test procedure across Zoom, Microsoft Teams, Slack, and Google Meet (in browser):

```
                                  MANUAL TEST MATRIX
  ┌───────────────────────┬───────────────────────┬───────────────────────┬───────────────────────┐
  │         ZOOM          │    MICROSOFT TEAMS    │    SLACK (HUDDLES)    │      GOOGLE MEET      │
  │     (zoom.exe +       │  (teams.exe / new MS  │  (slack.exe fallback  │   (chrome / msedge    │
  │     cpthost.exe)      │   Teams packaged)     │      UDP AF41)        │    UDP 19302-19309)   │
  └───────────────────────┴───────────────────────┴───────────────────────┴───────────────────────┘
```

### Test Procedure (Run for Each Target App):

1. **Idle Process Baseline Check (No Call):**
   - Launch target app. Sign in and keep running idle (do not join call).
   - In elevated PowerShell: `Get-NetQosPolicy -PolicyStore ActiveStore | Where-Object { $_.Name -like "NetGuard_*" }`
   - **Verification Requirement:** 0 NetGuard policies present. NetGuard UI status shows "في وضع الاستعداد (0 سياسة مطبقة)". DNS benchmarking is NOT frozen.

2. **Call Start & Dual-Condition Detection:**
   - Join an active video/voice call in the target app.
   - Verify mic/cam is captured in Windows: `Get-ItemProperty "HKCU:\Software\Microsoft\Windows\CurrentVersion\CapabilityAccessManager\ConsentStore\microphone\NonPackaged\*" | Select-Object PSChildName, LastUsedTimeStop` (`LastUsedTimeStop == 0`).
   - Observe NetGuard poller: within 5 seconds (enter hysteresis), status shifts from `ENTERING` to `ACTIVE`.

3. **ActiveStore Policy Confirmation (Readback):**
   - In elevated PowerShell:
     ```powershell
     Get-NetQosPolicy -PolicyStore ActiveStore | Select-Object Name, Precedence, AppPathNameMatchCondition, IPProtocolMatchCondition, DSCPAction, ThrottleRateActionBitsPerSecond | Format-Table -AutoSize
     ```
   - **Verification Requirement:**
     - Target app media policy appears with `Precedence 200` and `DSCPAction 34`.
     - Zoom includes screen sharing (`cpthost.exe`).
     - DNS exemption policies appear with `DSCPAction 0` and `Precedence 160`.
     - Bulk throttle policies appear with `DSCPAction 8` AND `ThrottleRateActionBitsPerSecond` (protocol `None`).
     - NetGuard UI badge shows: `"مطبقة ومؤكدة (N سياسة في ActiveStore)"` in green.

4. **Wireshark Live Tagging Verification:**
   - Start Wireshark capture on egress interface.
   - Apply filter: `ip.src == <PC_IP> && (dscp == 34 || dscp == 46 || dscp == 8 || dscp == 0)`.
   - Verify outbound UDP media packets carry DSCP 34 (AF41).
   - Verify background bulk upload packets carry DSCP 8 (CS1).
   - Verify DNS packets carry DSCP 0.

5. **Upload Saturation & Bufferbloat A/B Comparison:**
   - **A/B Baseline (QoS OFF / Kill Switch Pressed):**
     - Start unthrottled 100MB file upload (OneDrive/Google Drive).
     - Check call quality statistics panel in target app (e.g., Zoom Settings -> Statistics).
     - Observe packet loss ratio and RTT under saturation.
   - **A/B Enforced (QoS ON):**
     - Enable Master QoS in NetGuard.
     - Observe Task Manager: OneDrive egress throttled to adaptive remainder.
     - Observe in app statistics panel: packet loss ratio decreases and jitter stabilizes.
   - **Ethernet vs. Wi-Fi Comparison:**
     - Note that on Wi-Fi, AF41 maps to WMM `AC_VI` (3.008 ms TXOP); on Ethernet, 802.1p CoS maps to Priority Queue 4.

6. **Call End & Leave Hysteresis Teardown:**
   - Leave the meeting and mute/close camera.
   - NetGuard enters `LEAVING` state. During 20-second leave hysteresis, policies remain in place to protect against brief reconnection drops.
   - At 20.1 seconds: NetGuard tears down all policies via `Remove-NetQosPolicy`.
   - Run `Get-NetQosPolicy -PolicyStore ActiveStore`: 0 `NetGuard_*` rules remain.

## 5. Proven Conclusions vs. Working Hypotheses

The table below strictly separates verified empirical facts from hypotheses that require individual field measurements.

### Table A: PROVEN (Verified by Unit Tests, OS Verification, and Packet Dissection)
1. **Windows Host QoS is strictly egress-only:** `New-NetQosPolicy` controls only local host outbound transmission. Host PC software cannot rewrite or shape incoming packets delivered across the ISP downlink.
2. **Dual-Condition Meeting Gate prevents false triggers:** Requiring BOTH ConsentStore mic/cam capture (`LastUsedTimeStop == 0`) AND sustained outbound UDP traffic prevents idle background apps (e.g., Slack or Teams idling all day) from applying policies or freezing DNS.
3. **Simultaneous DSCP and Rate Action in one Cmdlet:** PowerShell `New-NetQosPolicy` accepts both `-DSCPAction 8` and `-ThrottleRateActionBitsPerSecond <bps>` simultaneously when `AppPathNameMatchCondition` is provided.
4. **Precedence Hierarchy protects DNS and signaling:** Assigning Precedence 200 (Media) > 170 (Probes) > 160 (DNS) > 150 (Signaling 443) > 100 (Throttle) > 50 (Default) guarantees that bulk demotion never demotes DNS (53) or NetGuard probes to `AC_BK`.
5. **ActiveStore policies survive process exit:** Policies created in `ActiveStore` survive application termination and are cleared only on system reboot or explicit removal. Startup sweep and watchdog reconciliation are mandatory.
6. **Two-Stage Closed-Loop Guard Rollback:** Pre-meeting baseline captured before apply enables detecting immediate post-apply quality degradation (+2% loss, +15ms jitter, +40ms RTT) and rolling back media marking first, then bulk policies.
7. **Downlink Limitation Honesty:** NetGuard transparently states in the UI and documentation that local PC QoS cannot shape downlink traffic from the ISP.

### Table B: WORKING HYPOTHESES (Requiring Real-World WAN Field Measurement)
1. **ISP DSCP Bleaching vs. Preservation:** Whether residential ISPs (e.g. in Egypt, Middle East, Europe) preserve DSCP tags past the first BNG/PE router or bleach (reset to 0) all markings. *Hypothesis: Most residential ISPs strip DSCP; primary benefit occurs on the home Wi-Fi/LAN hop.*
2. **Impact Magnitude on Upload Saturation:** The exact percentage reduction in latency jump under 100% upload saturation varies depending on the router's buffer depth (bufferbloat) and whether the upstream modem has SQM (CAKE/FQ-CoDel) enabled.
3. **Wi-Fi WMM Hardware Driver Mapping:** While RFC 8325 specifies AF41 mapping to AC_VI, certain legacy or budget 802.11n/ac Wi-Fi NIC drivers may ignore DiffServ and queue all frames into Best Effort (AC_BE).
